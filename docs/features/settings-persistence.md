# 📂 Settings & Configuration Persistence

## 📌 Overview
The Settings module manages application-wide configuration and ensures all user preferences are persisted across sessions. It uses a centralized store that bridges the UI with the local filesystem.

## 🏗️ Architecture
- **Entry Points**: 
  - `src/components/dialogs/SettingsDialog.tsx`
  - `src/lib/store.ts` (Tauri Plugin Store Integration)
- **Standard Defaults**: `src/lib/store.ts` defines `APPEARANCE_DEFAULTS`, `SHORTCUT_DEFAULTS`, etc.

## 🔄 Data Flow
1.  **Read**: On launch, components call `getSetting` to fetch initial values.
2.  **Write**: When a user adjusts a slider or toggle, `setSetting` is called.
3.  **Sync**: The Tauri backend writes changes to a local JSON file.
4.  **Reaction**: Components react to state changes via local React state or global event emitters (e.g., `cortex-demo-settings-changed`).

## 🛠️ Key Components
| Component | Responsibility |
| :--- | :--- |
| `SettingsDialog` | The multi-tab interface for configuring the workspace. |
| `store.ts` | The low-level abstraction for async storage operations. |
| `SettingsGroup` | Reusable UI sections within the dialog for grouping related settings. |

## 🧪 Verification & Testing
- **Key Scenarios**:
  - Toggling "Zen Mode" in settings immediately applies the UI padding changes.
  - Resetting settings to defaults successfully clears the local JSON store.
