# 📂 Workspace Management & Switching

## 📌 Overview
The Workspace Management module allows users to transition between multiple active spaces without terminating their underlying PTY sessions. It provides a visual registry of all initialized environments.

## 🏗️ Architecture
- **Entry Point**: `src/components/dialogs/WorkspaceSwitcherDialog.tsx`
- **State Management**: `src/lib/store.ts` (Persists the list of active workspaces)
- **Primary Hook**: `src/hooks/useWorkspaceDirectory.ts` (for path validation)

## 🔄 Data Flow
1.  **Trigger**: User activates the switcher via `Ctrl + K` or the header icon.
2.  **Selection**: User selects a different workspace from the grid.
3.  **Handoff**: `App.tsx` updates the `activeWorkspaceId`, triggering a re-render of `SpaceView` with the new configuration.
4.  **Persistence**: The "Active" state is maintained so the user returns to their last space on relaunch.

## 🛠️ Key Components
| Component | Responsibility |
| :--- | :--- |
| `WorkspaceSwitcherDialog` | The grid-based interface for selecting active environments. |
| `WorkspaceCard` | A compact preview of a workspace's layout, mode, and mounting path. |
| `ConfirmModeChangeDialog` | Prevents accidental data loss when switching between 'Normal' and 'Agents' spaces. |

## 🧪 Verification & Testing
- **Key Scenarios**:
  - Switching spaces preserves the scroll state and history of the underlying terminal panes.
  - Deleting a workspace correctly terminates all associated PTY processes.
